- 종목 행은 원래의 `종목명 / RSI·가격 / 별표` 3열을 유지한다. 신규 펼침 버튼을 없애고 행 클릭·키보드로 펼친다.
- 추가한 설정·밝은 화면·푸시 설정·거시/Study·그래프 팝업은 유지한다. 신규 기능에만 별도 CSS를 적용하고 전역 행/헤더 스타일을 덮어쓰지 않는다.
- 신규 거시 지표는 `현재 값 → 실제 비교 기준 → 쉬운 해석 → 함께 확인할 점` 순으로 읽는다. 자세한 설명과 그래프는 팝업에 둔다. 640px 이하는 추가 지표를 한 열로 배치한다.
- 자료 부족·지연은 현재 투자 환경의 판정과 구분한다. 새 투자 신호나 기준선을 임의로 만들지 않는다.
- 이번 브라우저 제어는 Work 설정으로 막혀 있다. 이전 실험 화면 관찰을 이번 최종 버전의 시각 QA로 대신하지 않는다.

## 1. 디자인 방향

**현재의 따뜻한 다크 톤, 상단 시장 카드, 다섯 개 탭, 접이식 종목 목록을 유지한다. 작은 글자와 낮은 대비를 개선하고, 숫자·판정·데이터 상태가 서로 구별되게 만든다.**

SAYO는 최소 5년을 바라볼 상품의 매수 기회를 확인하고, 중요한 변화가 생기면 보유 근거를 다시 살펴보는 도구다. 디자인도 차분한 관찰과 비교를 도와야 한다. 매매를 재촉하는 장식보다 종목명, 핵심 수치, 변화 이유, 자료의 기준시각을 읽기 쉽게 만드는 데 우선순위를 둔다.

이번 문서는 화면 디자인을 정한다. 거시 위험 임계값, RSI·PEG 기준, 매수 등급, 정렬 점수, 알림 발송 정책을 바꾸지 않는다. 예시의 종목·숫자·시각·판정은 레이아웃 설명용 합성 데이터다.

### 유지할 것과 개선할 것

| 유지 | 개선 |
| --- | --- |
| SAYO 로고와 따뜻한 어두운 배경 | 읽어야 할 보조 문자의 대비 |
| VIX·QQQ·KOSPI·환율의 기본 2×2 배치 | 카드 안에서 값·비교 기준·자료 상태의 자리 |
| 시그널 / 미장 / 국장 / ETF / 즐겨찾기 | 활성 탭, 키보드 초점, 누르기 쉬운 영역 |
| 국가별 접이식 목록과 종목 펼치기 | 긴 종목명, 숫자 정렬, 배지의 우선순위 |
| RSI와 가격을 빠르게 보는 요약행 | RSI·가격 라벨의 크기와 가독성 |
| 하단 공식 발표 패널 | 결과·예정·미확인 상태와 기준시각 |

## 2. 조사 방법과 한계

- 2026-10-24에 로그인 없는 공식 웹 화면과 공식 제품 이미지·도움말을 확인했다.
- 인기도 순위를 선정한 조사는 아니다. 국내 금융 정보의 읽기 방식, 다크 화면, 밀도 높은 목록, 장기 투자형 화면을 비교하기 위해 네 제품을 골랐다.
- 토스증권은 공개 웹의 실제 시장·목록 화면을 확인했다. TradingView는 공식 도움말에 있는 제품 스크린샷을 확인했다. Robinhood와 Wealthfront는 공식 사이트의 제품 소개 이미지까지 확인했다. 로그인 뒤 최신 앱 전체를 직접 조작한 것으로 해석하지 않는다.
- 외부 제품의 정확한 폰트 크기·간격·대비 수치를 측정한 것은 아니다. 관찰한 패턴과 SAYO를 위한 수치 제안을 구분한다.
- SAYO는 현재 로컬 CSS를 그대로 사용한 정적 합성 데이터 화면을 데스크톱 및 390·320 CSS px iframe에서 확인했다. 로고는 글자로 대체했고 일부 장식·운영 JavaScript는 제외했다. 운영 화면 전체나 실제 계정으로 한 사용성 검증은 아니다.
- 쿠키·브라우저 저장소·로그인 세션·사용자·관리자 자료는 읽지 않았다. 외부 화면의 자산을 다운로드하거나 디자인 결과물에 복제하지 않았다.

## 3. 외부 금융앱 화면 스터디

### 3.1 토스증권 — 한글 목록과 숫자 비교

출처: [토스증권 공개 웹](https://www.tossinvest.com/)

**관찰:** 공개 홈에서 시장 요약과 주요 일정을 위에 두고, 아래에 종목 목록을 배치한다. 목록은 종목명과 현재가·등락을 일정한 위치에 두며, 숫자와 설명 사이에 명확한 크기·색 차이가 있다. 행은 옅은 구분선과 여백으로 구분한다. 상승·하락 숫자는 부호와 색을 함께 쓴다.

**SAYO 적용:** 종목명과 수치의 정렬을 고정하고, 메타정보는 한 단계 낮은 시각적 위계로 둔다. 시장 카드에도 무엇과 비교한 변화인지 붙인다. 숫자 크기를 유지하면서 주변의 작은 라벨을 읽기 좋게 만든다.

**선별:** 실시간 인기 순위, 거래 유도 요소, 우측 다중 패널은 현재 SAYO의 기본 화면에 추가하지 않는다. 밝은 테마를 그대로 이식하지 않는다.

### 3.2 TradingView — 정보 분류와 안정적인 열

출처: [Watchlist advanced view mode](https://www.tradingview.com/support/solutions/43000771546-watchlist-advanced-view-mode/)

**관찰:** 공식 예시는 가격·재무·성과·위험·기술 지표를 목적별로 나누고, 실적·배당·뉴스도 별도 영역으로 구분한다. 표의 숫자 열과 종목 행이 정렬돼 있어 항목 간 비교가 쉽다.

**SAYO 적용:** 종목을 펼치면 지표를 ‘가격과 가치 / 이익 전망 / 산업·거시 근거 / 출처와 시각’으로 묶는다. 같은 종류의 값은 같은 자리에 둔다. 첫 화면에 모든 분석값을 늘어놓지 않는다.

**선별:** 전문 차트 도구모음, 다중 창, 수십 개 기술 지표는 추가하지 않는다. 새로운 최상위 탭 대신 기존 펼침 영역을 활용한다.

### 3.3 Robinhood — 어두운 면에서 핵심 요소 구별

출처: [공식 Trading 제품 페이지](https://robinhood.com/us/en/about/trading/), [Watchlists and cards](https://robinhood.com/us/en/support/articles/watchlist-and-cards/)

**관찰:** 공식 제품 페이지는 짙은 배경과 밝은 주요 문자를 크게 구분한다. 모바일 차트 소개 이미지는 가격·차트·도구를 별도의 층으로 보여준다. 도움말은 관심목록과 카드 구성을 설명한다.

**SAYO 적용:** 주요 수치는 밝게, 설명은 충분히 읽히는 중간 밝기로 구분한다. 색은 선택 상태와 중요한 판정에 집중한다. 모든 카드가 동시에 강하게 보이는 효과는 줄인다.

**선별:** 네온색, 거대한 홍보 타이포그래피, 거래 버튼, 입체 제품 장식은 차용하지 않는다. 제품 이미지의 연출을 실제 앱 전체의 사용성으로 일반화하지 않는다.

### 3.4 Wealthfront — 짧은 설명과 목록의 구분

출처: [공식 Brokerage 페이지](https://www.wealthfront.com/brokerage)

**관찰:** 공식 모바일 예시는 Core ETFs와 Popular stocks를 나누고, 상품명과 티커를 두 단계로 표시한다. 화면의 설명은 짧고, 각 영역의 목적을 제목으로 알려준다.

**SAYO 적용:** 상품명과 티커를 구별하고, 접이식 영역은 짧은 제목과 설명으로 안내한다. 상태 설명은 한 문장으로 시작하고 근거는 펼쳐서 읽는다.

**선별:** 계좌 잔액 중심 홈, 자산배분 기능, 수익률 홍보 영역을 SAYO에 추가하지 않는다. 예시는 공식 홍보용 화면이라는 한계가 있다.

## 4. 현행 화면 진단

근거는 로컬 작업 트리의 `public/index.html`이다. 기존 미커밋 변경도 포함해 읽었으며 수정하지 않았다. 중복 CSS 정의가 있으므로 아래 진단은 선언 한 개만 보고 한 판단과 실제 합성 화면 관찰을 구분한다.

| 항목 | 확인한 사실 | 디자인 판단 |
| --- | --- | --- |
| 보조 텍스트 | `--fg-4: #5e5854`가 요약 라벨·설명 등에 사용됨 | 읽어야 할 내용에 쓰기에는 어둡다 |
| 작은 글자 | 여러 라벨·배지·상세 항목이 10~11px | 정보 밀도에 비해 글자가 작다 |
| 요약 수치 | 모바일 마지막 규칙에서 가격 12px, RSI 15px | 주요 수치와 라벨의 위계를 다시 정할 필요 |
| 긴 이름 | 종목명에 한 줄·말줄임 규칙 적용 | 긴 ETF의 식별 가능한 이름을 확인하기 어렵다 |
| 배지 | 후보·강력 매수 색상이 비슷하고 상태 배지가 함께 배열됨 | 신호·산업 판단·자료 상태를 구분해야 한다 |
| 즐겨찾기 | 버튼 26×26px | 모바일의 권장 조작 영역을 넓힐 여지가 있다 |
| 시장 카드 | 수치·MA·상태는 있지만 원천시각 표시가 일관되지 않음 | 시장 상태와 자료 상태가 혼동될 수 있다 |
| 상단 상태 | ‘최근 업데이트’, ‘시그널 탐지 중’ 표시 | 수집 완료·검토 완료·시장 관측을 구분할 문구가 필요 |
| 반응형 CSS | 같은 선택자의 재정의와 여러 미디어쿼리가 있음 | 새 덮어쓰기 추가 전에 최종 적용 규칙을 정리해야 한다 |
| 확대 | viewport에 `maximum-scale=1.0, user-scalable=no`가 있음 | 확대 제한 선언을 제거하고 확대 동작을 검증해야 한다 |

### 계산으로 확인한 대비

WCAG 상대휘도 공식으로 단색 토큰 조합을 계산했다. 반투명 배지, 실제 합성 배경, hover·focus 등 모든 상태의 적합성을 확인한 표는 아니다.

| 전경 / 배경 | 대비 | 일반 크기 텍스트 목표 4.5:1 |
| --- | ---: | --- |
| `#5e5854` / `#2b2825` | 2.09:1 | 미달 |
| `#5e5854` / `#353230` | 1.82:1 | 미달 |
| `#948d87` / `#2b2825` | 4.48:1 | 미달 |
| `#948d87` / `#353230` | 3.89:1 | 미달 |
| `#c9c2bc` / `#2b2825` | 8.32:1 | 충족 |

`4.48`을 반올림해 적합으로 취급하지 않는다. 일반 텍스트 4.5:1, 큰 텍스트 3:1 기준의 출처는 [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)이다.

- 넓은 화면의 4열 카드 전환은 후속 선택안이다. 초기 개선의 필수 범위가 아니다.

## 6. 타이포그래피·색·간격

### 6.1 글자

사용자는 윤고딕을 우선 요청한 뒤, 보유 웹폰트가 없어 웹 사용 가능한 유사 고딕체로 대체하는 데 동의했다. 기존 Pretendard를 모든 인터페이스 텍스트에 통일하고 현재의 고정폭 숫자 설정(`tabular-nums`)을 유지한다. 본문은 400~500, 핵심 수치·제목은 최대 600을 기본으로 하여 굵기 사용을 절제한다. 전역 글자 크기를 일괄 확대하기보다 컴포넌트별 크기와 줄바꿈을 조정한다.

| 용도 | 권장 크기 | 굵기 / 행간 |
| --- | --- | --- |
| 시장 주요 수치 | 24~28px | 600 / 1.2 |
| 종목명 | 모바일 15~16px, 데스크톱 16px | 500~600 / 1.4 |
| 종목 가격·RSI | 모바일 15~17px | 500~600 / 1.3 |
| 일반 설명·변화 이유 | 14~15px | 400~500 / 1.55 |
| 라벨·시각·티커 | 12~13px | 450~550 / 1.45 |
| 상태 배지 | 12px | 550~600 / 1.3 |

판단에 필요한 문자를 10px로 압축하지 않는다. 데이터 수가 많으면 그룹·접기·줄바꿈으로 해결한다. ‘본문 최소 14px’ 등은 SAYO의 디자인 목표이며 WCAG의 보편적 최소 글자 크기 규정으로 설명하지 않는다. 상용 윤고딕 파일을 임의로 복제하거나 폰트가 설치되지 않은 환경에서 적용됐다고 표시하지 않는다.

### 사용자 확정 추가 요구

- 설정 화면에서 이 기기의 푸시 수신 ON/OFF와 다크·화이트 모드를 조절한다. 푸시 수신 설정은 승인 상태와 별개로 저장하고 발송 서버가 적용한다.
- 자료 이력이 있는 지표는 클릭하면 팝업에서 값/그래프를 전환한다. 데이터가 부족하면 이유를 표시하고 임의의 그래프를 만들지 않는다.
- 팝업에는 닫기·Escape·초점 복귀를 제공하며 배경 스크롤을 제어한다.

### 6.2 색 토큰 제안

기존 배경 계열은 유지한다. 다음 색은 구현 시작점이며 실제 배경과 상태별 검증 후 확정한다.

```css
:root {
  --bg-0: #1a1816;
  --bg-1: #221f1d;
  --bg-2: #2b2825;
  --bg-3: #353230;

  --text-primary: #f0ebe5;
  --text-secondary: #d0c8c0;
  --text-muted: #b4aaa0;

  --status-positive: #8bc8ab;
  --status-warning: #ebbe83;
  --status-risk: #ef9691;
  --status-info: #9bc7e8;
  --focus-ring: #9bc7e8;
}
```

`--text-muted`는 `--bg-3` 위에서 약 5.57:1이다. 위 네 상태색은 같은 면 위에서 약 5.72~7.41:1이다. 반투명 배지 면에 적용할 때는 합성된 실제 배경으로 다시 계산한다. 비활성·장식용 어두운 회색을 읽어야 할 데이터와 시각에 재사용하지 않는다.

가격의 상승·하락, 기업 전망의 개선·악화, 데이터의 최신·만료는 서로 다른 의미다. 현행 가격·추세 색 관습을 일괄 변경하지 않고 부호·라벨을 함께 제공한다. VIX 상승을 일반적인 ‘긍정’ 색으로 해석하지 않는다.

### 6.3 간격과 표면

- 간격 단계: 4 / 8 / 12 / 16 / 24 / 32px.
- 모바일 좌우 여백 12~16px, 카드 내부 14~16px, 종목 간 구분은 일정한 선과 여백으로 유지한다.
- 카드 모서리는 기존 8~10px 계열을 유지한다. 그림자·발광을 기본 구분 수단으로 사용하지 않는다.
- 읽을 영역에는 여백을 주고, 반복 장식에는 공간을 과하게 쓰지 않는다.

## 7. 컴포넌트별 설계

### 7.1 시장 카드

```text
VIX                      직전값
19.45
5일 평균 18.18
관측 10/23 미국 종가             ⓘ
```

위 예시는 자리 배치를 위한 합성 값이다. 실제 필드가 없으면 ‘관측 시각 확인 불가’로 표시한다.

- 읽는 순서: 지표명 → 현재값 → 명시된 비교 기준 → 원천시각·자료 상태.
- 정상적인 종가에는 ‘미국 종가’, ‘한국 종가’ 등 세션을 표시할 수 있다. 주말이라는 이유만으로 오류 색을 쓰지 않는다.
- 직전값·만료일 때 숫자는 읽을 수 있게 유지하고, 과거 판정에는 ‘직전 판정’임을 붙인다. 최신 관측처럼 평온 배지를 보여주지 않는다.
- 수집 시각을 시장 관측 시각으로 대신 쓰지 않는다. 이 규칙에는 데이터 계약 보완이 필요하다.
- 미니 차트는 충분한 이력이 제공될 때 후순위로 검토한다. 초기 CSS 개선에는 포함하지 않는다.

### 7.2 종목 요약행

```text
엔비디아                         RSI       가격    ☆
NVDA · AI 반도체                 42.5    $182.30
[매수 후보] [사이클 중립]                 상세 ▾
```

- 첫 시선은 종목명, 그다음 RSI·가격이다. 익숙한 요약 항목을 유지한다.
- 숫자는 우측 정렬하고 자릿수가 바뀌어도 흔들리지 않게 한다. 통화 단위를 유지한다.
- 모바일에서 긴 ETF명은 최대 두 줄까지 허용하고, 종목명이 숫자·즐겨찾기와 겹치지 않게 한다. 더 긴 이름은 펼침 영역에서 전체를 읽을 수 있게 한다.
- 360px 미만에서는 종목 식별 영역과 수치 영역을 두 줄로 나눌 수 있다. 글자를 줄여 끼워 넣지 않는다.
- 시그널 배지와 산업 배지는 유지하되 자료 상태는 구별되는 텍스트로 둔다. 배지가 많으면 추가 정보는 펼침 영역으로 이동하되, 위기·만료 같은 중요한 상태는 접힌 상태에서도 보인다.
- 데스크톱의 표 헤더와 실제 요약행 항목을 일치시킨다. 새 설계도 현재 렌더 함수가 요약행 중심이라는 사실을 기준으로 구현한다.

### 7.3 상태의 세 가지 의미

| 종류 | 예 | 시각적 처리 |
| --- | --- | --- |
| 매수 조건 | 매수 후보·강력 매수·지금 매수 | 기존 등급명·주요 색 계열 유지, 가장 앞의 배지 |
| 사업·산업 판단 | 사이클 우호·중립·주의 | 별도 테두리 또는 옅은 면, ‘사이클’ 접두어 |
| 자료 상태 | 직전값·만료·확인 불가 | 시계·주의 아이콘과 명시적 문구, 기준시각 연결 |

색 하나만으로 세 의미를 전달하지 않는다. ‘매수 후보’와 ‘사이클 주의’가 함께 있을 때 한쪽을 지우거나 새 점수로 합치지 않는다. 각각의 의미와 근거를 펼쳐 읽는다.

자료 부족 때문에 중립인 경우에는 ‘사이클 중립 · 근거 부족’을 표시할 수 있다. 그 사유가 데이터에 없으면 프런트가 추정하지 않고 ‘판정 사유 확인 불가’로 표시한다.

### 7.4 종목 상세

기존 펼치기를 유지하고 아래 순서로 정리한다.

1. **현재 조건:** 기존 신호의 실제 충족·미충족 근거. 근거가 제공되지 않으면 새로 만들지 않는다.
2. **가격과 가치:** PEG·PER·PBR·PS·52주 위치. 상품에 해당하는 값만 표시한다.
3. **이익 전망:** EPS·목표가 추세, 성장률, 실적 서프라이즈. 성장 기간과 비교 기간을 명시한다.
4. **산업·거시 점검:** 핵심 변화, 반대 근거, 관련 상품에 미치는 경로. 구조화된 데이터가 준비된 뒤 표시한다.
5. **다음 확인·출처:** 공식 발표 일정, 원문, 원천시각, 마지막 검토시각.

수치는 2열 그리드를 기본으로 한다. 변화 이유 같은 문장은 전체 폭을 사용한다. 원문 링크는 짧은 출처명과 날짜를 쓰고 길고 복잡한 URL을 본문에 노출하지 않는다.

커버드콜 월분배금은 기존 계산 영역을 유지한다. ‘최근 실제 기준 / 목표 기준’과 기준 월을 금액 가까이에 표시한다. 자료 상태를 펼침 가장 아래에만 숨기지 않는다.

### 7.5 Study·거시 요약 — 데이터 준비 후

```text
이번 점검에서 바뀐 내용
금리 부담 확대 · 산업 수요 판단 유지
관련 대상 3개  /  검토 10/24 08:00 KST
변화 근거와 다음 확인 일정 보기 ▾
```

최대 두 줄의 요약으로 시작한다. 필수 의미를 말줄임으로 숨기지 않고 큰 글자에서는 자연스럽게 늘어난다. 숫자 없는 추상적인 낙관·비관 문장을 반복하지 않는다. ‘검토 완료’, ‘변화 없음’, ‘검토 자료 부족’은 구별한다.

### 7.6 로딩·빈 상태·부분 실패

| 상황 | 권장 문구·동작 |
| --- | --- |
| 첫 로딩 | 기존 영역과 비슷한 높이의 정적 스켈레톤 + ‘시장 데이터 확인 중’ |
| 조건 충족 종목 없음 | ‘현재 조건을 충족한 종목이 없습니다’ |
| 관심 종목 없음 | ‘별표를 눌러 자주 볼 종목을 모아보세요’ |
| 일부 자료 실패 | ‘일부 지표는 직전값으로 표시합니다’ + 해당 항목으로 이동 |
| Study 만료 | ‘Study 검토 자료가 만료됐습니다’ + 마지막 검토일·출처 |
| 다음 일정 미확인 | ‘다음 공식 발표일 확인 중’ |

빈 목록과 불러오기 실패를 같은 문구로 처리하지 않는다. 실제 실패나 직전값이 있는데 ‘시그널 탐지 중’만 표시하지 않는다.

## 8. 숫자·문구·상호작용 규칙

- `19.45`, `+0.03%`, `+0.25%p`, `$182.30`, `₩1,326.90`처럼 단위와 비교 기준을 분리하지 않는다. `%`와 `%p`를 혼용하지 않는다.
- 지표별 표시 자릿수를 고정한다. 원천값과 신호 계산값은 유지하며, 화면용 반올림 규칙만 명시한다.
- 실제 0과 결측 `—`를 구별한다. 결측 이유는 인접 문구 또는 상세에서 설명한다.
- 같은 날은 시각과 시간대, 오래된 값은 날짜까지 표시한다. 여러 시장을 다루므로 필요 시 미국·한국 세션도 명시한다.
- 이모지는 기존 정체성을 해치지 않는 범위에서 정리한다. 배지마다 이모지를 여러 개 중첩하지 않는다.
- 종목 펼치기와 국가별 접기는 버튼 또는 동등한 키보드 조작을 제공하고 `aria-expanded`·`aria-controls`를 연결한다. 별표 동작과 펼치기가 중복 실행되지 않게 한다.
- 즐겨찾기 아이콘은 현재 크기를 유지해도 조작 영역은 44×44px를 권장한다. 이는 SAYO의 사용성 목표다. WCAG 2.2 AA의 기본 최소 기준은 예외 조건을 포함한 24×24 CSS px다. [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- `:focus-visible`을 명확히 제공하고, 탭·펼치기·링크에서 초점이 사라지지 않게 한다. 새로운 고정 헤더가 초점을 덮지 않게 한다.
- 확대 제한을 제거하고 200% 텍스트 확대를 확인한다. 320 CSS px에서 일반 목록·카드가 가로 스크롤 없이 재배치되게 한다. [Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html), [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- `prefers-reduced-motion`에서는 맥박·반복 깜박임을 줄인다. 새 데이터 수신 시 화면 전체나 모든 숫자를 점멸시키지 않는다.

## 9. 구현 단계를 분리한다

| 단계 | 범위 | 의존성 |
| --- | --- | --- |
| **P0 가독성** | 글자 대비·라벨 크기·숫자 정렬·긴 이름·초점·조작 영역·확대 허용 | 기존 프런트 중심 |
| **P1 상태 전달** | 지표별 직전값·만료·시각, 중립 사유, 일부 실패 안내 | 현재 필드부터 적용, 부족한 필드는 계약 보완 |
| **P2 분석 연결** | 시장 변화 요약, 종목별 영향, Study 반대 근거·다음 점검 | 검증된 구조화 데이터와 분석 프로세스 |
| **P3 선택 개선** | 추가 거시 지표 상세, 넓은 화면 4열, 작은 추세 차트 | 실제 데이터·사용성 검증 후 |

P0를 진행하면서 신호 계산이나 운영 주기를 바꾸지 않는다. P1·P2에서 데이터가 없는 영역을 임의의 문장이나 현재 시각으로 채우지 않는다. 시장 상태·산업 상태를 프런트에서 독자적으로 재계산하지 않는다.

- [ ] 320 / 360 / 390 / 430 / 768 / 1280px에서 주요 수치·이름·버튼이 겹치지 않는다.
- [ ] 긴 한국어 ETF명, 긴 티커, 큰 원화 가격, 소수 가격으로 확인한다.
- [ ] 일반·직전값·만료·누락·부분 실패·로딩·빈 목록 상태를 각각 확인한다.
- [ ] 일반 텍스트는 실제 배경 대비 4.5:1 이상, 큰 텍스트는 적용 조건에 맞춰 3:1 이상이다.
- [ ] 배지의 반투명 배경·활성·hover·focus 상태까지 별도 측정한다.
- [ ] 시각·출처·지표 라벨은 정상 시력에서 읽기 쉬운 크기이며 색만으로 의미를 전달하지 않는다.
- [ ] 키보드만으로 탭 선택·종목 펼치기·즐겨찾기·출처 열기를 할 수 있다.
- [ ] 200% 텍스트 확대와 320 CSS px 재배치에서 정보·기능이 사라지지 않는다.
- [ ] 데이터 갱신 후에도 펼침·초점·스크롤 위치가 불필요하게 초기화되지 않는다.
- [ ] UI 개선으로 신호 등급·기준·정렬·알림 정책이 달라지지 않는다.
- [ ] 성능 비교 시 콜드·웜 조건, HTML 수신·첫 시장 데이터·첫 의미 있는 렌더를 분리한다.
- [ ] 같은 합성 데이터로 변경 전후 문서 크기·렌더 횟수·화면 밀림을 비교한다. 실제 계정은 사용하지 않는다.

사용성 목표는 ‘3초 내 종목·핵심 수치 식별, 10초 내 자료 신선도와 주의 이유 확인’으로 잡는다. 이는 검증할 목표이며 이미 입증된 성과가 아니다.

## 11. 구현 지점과 변경 관리

| 현행 지점 | 후속 작업 |
| --- | --- |
| `:root`, `.macro-*`, `.stock-row-summary` | 글자·색·정렬 토큰 정리 |
| `.stock-row-header`, `.col-name`, 모바일 미디어쿼리 | 긴 이름·수치 재배치 |
| `.badge`, `.cycle-*`, 상태 렌더링 | 판정과 자료 상태의 시각 구분 |
| `renderMacro()`, `renderMacroPolicy()` | 원천 시각·만료·누락 표시 |
| `renderStockRow()` 및 실제 호출 경로 | 상세 지표 그룹·근거 연결 |
| `.event-panel`, 이벤트 렌더링 | 발표 상태·검토 상태·시각 정리 |
| 탭·펼치기·즐겨찾기 이벤트 | 키보드·접근성·선택 상태 보존 |

이번 조사에서는 기존 사용자 변경이 있는 `config.py`, `public/index.html`, `test_frontend_entry_flow.py`를 수정하지 않았다. 후속 구현 시 그 변경을 기준으로 작은 단위로 적용한다. 중복 CSS를 새 규칙으로 계속 덮기보다 최종 적용 규칙부터 정리한다.

문서 작성 시 완료한 검증은 공식 화면 시각 조사, 현행 CSS의 합성 화면 확인, 단색 토큰 대비 계산이다. 새 디자인의 구현·접근성 적합성 전체 검증·실사용자 테스트·배포는 아직 수행하지 않았다.
