# Stock SAYO Study 프로젝트 기본 지시

## 역할과 제품 원칙

- 이 프로젝트는 반도체 사이클을 조사·표시하는 별도 HTML 분석 페이지다. 투자 자문, 목표가, 매수·매도 지시를 만들지 않는다.
- Stock SAYO는 이 프로젝트가 발행한 구조화된 JSON을 읽어 관련 주식에 `사이클 우호 / 중립 / 주의` 보조 컴포넌트를 표시하는 소비자다. 이 프로젝트는 SAYO의 밸류에이션·타이밍 조건을 바꾸거나, 매수 후보를 만들지 않는다.
- 사이클 상태의 사용자 표기는 `사이클 우호`, `사이클 중립`, `사이클 주의`만 사용한다. `우호`는 강한 매수 추천이 아니며, `주의`는 매도 지시가 아니다.
- 반도체 리포트의 모델 분업·증거·확정 규칙은 [SEMICONDUCTOR_CYCLE_AI_ROLES.md](SEMICONDUCTOR_CYCLE_AI_ROLES.md)를 단일 기준으로 삼는다. 관련 작업 전에는 반드시 읽는다.

## 짧은 요청을 해석하는 기본 방식

사용자가 “이거 반영해”, “붙여줘”, “만들어줘”처럼 짧게 요청하면 다음을 스스로 수행한다.

1. 관련 코드와 문서를 먼저 찾아 현재 동작·데이터 흐름·기존 변경 사항을 확인한다.
2. 요청이 아래 어느 범주인지 판단한다.
   - 분석 페이지·주간 리포트 변경
   - JSON 계약 또는 배포 변경
   - Stock SAYO 소비자와의 호환성 변경
3. 최소 변경으로 구현하고, 관련 테스트 또는 정적 검증을 실행한다.
4. 변경 사항, 검증 결과, 남은 가정만 간결하게 보고한다.

안전하고 되돌릴 수 있는 구현 세부 사항은 질문하지 말고 합리적으로 결정한다. 다만 사용자 자금·외부 계정·유료 서비스·프로덕션 배포·파괴적 변경처럼 권한이나 범위가 달라지는 일은 실행 전에 확인한다.

## 전체 현행화 단축 요청

- 사용자가 `사요 스터디/웹앱 현행화해줘`, `사요 전체 업데이트`, `스터디와 지표 최신화`, `모든 갱신 작업 한 번 돌려줘` 또는 의미가 같은 표현을 쓰면 개인 스킬 `$sayo-refresh-all`의 전체 흐름을 실행한다.
- 이 표현은 이번 한 회차의 공식 자료 수집, AI 근거 감사, 이벤트·사이클·정량 빌드, 운영 Git 커밋·push, Study Hosting 배포, SAYO 수집 실행과 공개 대조에 대한 명시적 승인으로 간주한다. 계획만 보고하고 멈추지 않는다.
- 운영 Git 기준은 `/Users/jay/projects/stock-sayo`이고 `/Users/jay/projects/stock-sayo-study`는 Study 실행 작업장이다. 두 사본은 파일별 신선도와 검증 내용을 비교해 병합하며, 더 최신인 이벤트 결과나 기존 사용자 변경을 통째로 덮어쓰지 않는다.
- 공식 출처 일부가 실패하면 유효기간만 연장하지 않는다. 검증된 사이클·정량은 배포하되 이벤트는 `stale · 직전값 사용`으로 보존하고 SAYO가 만료 피드를 정상값으로 수용하게 만들지 않는다.
- 유료 자원 생성, 영구 스케줄 변경, 알림·매수 조건 변경은 전체 현행화 단축 요청의 승인 범위에 포함하지 않는다.

## 분석 페이지와 Stock SAYO의 경계

- 분석 페이지는 사람이 읽는 HTML 리포트와 기계가 읽는 JSON을 함께 발행한다.
- Stock SAYO는 HTML을 스크래핑하거나 AI에게 리포트 내용을 재해석시키지 않는다. 버전·생성 시각·만료 시각이 있는 검증된 JSON만 읽는다.
- JSON이 없거나 만료·검증 실패할 때 Stock SAYO가 `사이클 중립 · 데이터 갱신 대기`로 폴백할 수 있도록, 마지막 유효 발행본과 명시적인 만료 시각을 유지한다.
- 분석 페이지의 리포트 형식이나 JSON 계약을 바꿀 때는 생산자와 소비자 변경을 함께 처리하고, 하위 호환 또는 명시적 버전 전환을 제공한다.

## 반도체 사이클 데이터 원칙

- 반도체를 하나의 사이클로 일반화하지 않는다. 최소 세그먼트는 메모리(HBM/DRAM), NAND, 파운드리/로직, 장비/소부장, 아날로그/자동차·산업용으로 나눈다.
- 1차 출처(기업 IR·실적발표·공시, WSTS, SEMI, 거래소 공시)를 우선한다. 출처 URL, 발행일, 출처군, 세그먼트 없이 상태를 바꾸지 않는다.
- 긍정 근거와 반대 근거를 함께 보존·표시한다. 증거가 부족하거나 충돌하면 `중립`이 기본값이다.
- `우호`/`주의` 확정에는 서로 다른 출처군 2개 이상과 증거 축 2개 이상이 필요하다. 같은 보도자료를 인용한 여러 기사는 독립 출처로 세지 않는다.

## AI·토큰 효율 원칙

- 코드 검증, 스키마 검증, 날짜·출처·중복 검사, 정적 빌드·배포는 AI 없이 처리한다.
- 반복 수집·추출·형식화는 Terra의 낮은 추론 수준을 우선한다.
- 상충 증거 해석, 세그먼트 국면 제안, 상태 변경 감사처럼 오류 비용이 큰 작업만 Sol의 높은 추론 수준을 사용한다.
- Sol을 기본값으로 사용하거나, 원문 웹페이지 전체를 여러 번 재분석하지 않는다. 먼저 구조화된 증거 JSON을 만들고, 상태 변경 후보에만 Sol을 호출한다.
- AI의 출력은 사실·근거·제안으로 구분해 저장한다. 검증 규칙이 통과하지 않은 AI 제안은 사용자 서비스에 반영하지 않는다.

## 구현·검증 규칙

- 기존 사용자 변경과 무관한 파일을 되돌리거나 덮어쓰지 않는다.
- 변경은 작고 읽기 쉽게 유지한다. 데이터 계약은 명시적인 스키마·예시·폴백을 둔다.
- 신호 로직을 바꾸면 정상·경계·데이터 누락 사례를 검증한다. UI를 바꾸면 실제 렌더링 또는 가능한 범위의 정적 검증을 수행한다.
- 비밀값, API 키, 사용자 데이터는 코드·리포트·로그에 넣지 않는다.
- 테스트를 실행하지 못했다면 이유와 실행하지 않은 범위를 최종 보고에 적는다.

## 기본 응답 언어와 보고 형식

- 사용자에게는 한국어로 답한다.
- 최종 보고는 결과를 먼저 말하고, 변경 파일·검증·남은 주의점만 짧게 적는다.
