# 주간 반도체·AI 리포트 운영 계획

## 목표와 범위

- 매주 토요일 07:00 KST에 검증된 공개·라이선스 자료를 수집해 사람이 읽는 HTML과 기계가 읽는 JSON을 함께 발행한다. 여기서 “학습”은 모델 재학습이 아니라 공식 자료를 주간 지식베이스에 수집·정규화·검증해 리포트를 갱신한다는 뜻이다.
- 리포트는 산업·세그먼트의 `사이클 우호 / 사이클 중립 / 사이클 주의` 보조 상태만 표시한다. 투자 의견, 목표가, 매수·매도 지시는 만들지 않는다.
- 상태 변경은 기업 IR·실적발표·공시, WSTS, SEMI, 거래소 공시 같은 1차 출처를 우선한다. 월스트리트 저널 등 유료 매체는 유효한 구독 또는 라이선스 API·RSS가 있을 때만 보조 맥락으로 사용한다. 페이지 우회 수집은 하지 않는다.

## 단계별 진행 순서

1. **초기 배포** — 현재 정적 `index.html`을 Firebase Hosting의 `https://stock-sayo-study.web.app/`에 배포한다.
2. **데이터 계약** — `cycle-latest.json` 스키마를 정한다. `report_id`, 생성·만료 시각, 세그먼트, 근거 URL·발행일·출처군·증거축, 반대 근거, 상태를 포함한다.
3. **수집기** — 허용 도메인과 RSS/API 목록만 코드에 등록한다. 자료는 원문 링크·날짜·출처군·세그먼트가 있는 경우만 증거 후보로 저장한다.
4. **검증·판정** — 중복 URL·날짜·출처군을 규칙으로 검증한다. 서로 다른 출처군 2개와 증거 축 2개가 없거나 근거가 상충하면 기본값은 `사이클 중립`이다.
5. **리포트 생성** — 검증을 통과한 자료만 HTML과 JSON에 반영하고, 이전 주와의 차이 및 반대 근거를 함께 보여 준다.
6. **자동 실행·배포** — GitHub Actions 또는 Cloud Scheduler에서 토요일 07:00 KST(금요일 22:00 UTC)에 실행한다. 검증 실패 시 마지막 유효 발행본을 유지하고 만료 시각 이후에는 `사이클 중립 · 데이터 갱신 대기`를 발행한다.

## 실제 코드 흐름

1. `collect_sources.py`가 허용 도메인만 읽고 제목·직접 발행일·짧은 본문 발췌·콘텐츠 해시를 `data/inbox.json`에 저장한다.
2. `review_candidates.py`가 신규 해시와 최근 30일의 직접 발행일 항목만 GPT-5.6 Terra(low)에 전달한다. 원문 전체나 임의 웹 검색은 모델 입력에 넣지 않는다.
3. 신뢰도 70 이상, 상태 변경 가능성, 상충 근거는 GPT-5.6 Sol(high)의 별도 반대 의견 감사를 거친다. 감사 이유와 모델은 로그에 남긴다.
4. `apply_review.py`가 출처 도메인·직접 발행일·허용 세그먼트·증거 축·사실 길이를 코드로 다시 검증한 뒤 `data/evidence.json`에만 승격한다.
5. `cycle_engine.py`는 감사 통과 근거 중 독립 출처군 2개와 증거 축 2개가 있는 경우에만 우호·주의를 확정한다.
6. 단위 테스트와 정적 계약 검증이 실패하면 커밋·배포 단계가 실행되지 않아 마지막 유효 발행본이 유지된다. API 키가 없으면 AI 단계만 생략하고 임의 근거를 만들지 않는다.

## 안전장치

- 세그먼트는 `memory_hbm_dram`, `memory_nand`, `foundry_logic`, `equipment_materials`, `analog_auto_industrial`로 분리한다.
- 동일 보도자료를 재인용한 복수 기사는 독립 출처로 계산하지 않는다.
- `우호`와 `주의`는 각각 독립 출처군 2개 이상, 증거 축 2개 이상, 반대 근거 노출을 충족해야 한다.
- AI는 구조화된 자료의 추출·분류·감사에만 쓰며, 검증 규칙을 통과하지 않은 제안은 발행하지 않는다.
- 자격증명과 유료 데이터 키는 GitHub/Firebase의 비밀값에만 저장하고 저장소·리포트·로그에 넣지 않는다.
