# 반도체 사이클 리포트: AI 역할·모델 운영 기준

## 목적

주간 반도체 사이클 리포트는 **AI의 서술을 투자 판단으로 사용하지 않는다**. AI는 공식 자료를 수집·정규화·요약하고, 정해진 증거 규칙을 통과한 경우에만 `사이클 우호 / 중립 / 주의` 상태를 제안한다.

SAYO는 확정된 JSON을 보조지표로만 사용한다. 밸류에이션 또는 매수 타이밍 조건을 우회하거나, 사이클 결과만으로 매수 후보를 만들 수 없다.

## 모델 원칙

현재 Codex에서 사용하는 모델은 아래 두 가지로 한정한다.

| 모델 | 기본 용도 | 사용 기준 |
| --- | --- | --- |
| **GPT-5.6 Terra** | 반복 수집, 분류, 형식화, 일반 코드 작업 | 기본 모델. 낮거나 중간 수준의 추론으로 충분한 모든 작업에 사용한다. |
| **GPT-5.6 Sol** | 상반된 증거 해석, 세그먼트 국면 판정, 상태 변경 감사 | 잘못된 결론의 비용이 큰 경우에만 사용한다. |

Sol을 기본값으로 쓰지 않는다. Sol 호출은 주간 리포트에서 `우호 ↔ 주의` 상태가 바뀌거나, 신뢰도가 높아지는 경우에만 발생해야 한다.

## 역할 분리

| 단계 | 담당 | 모델 / 추론 수준 | AI 출력 | AI 없이 검증할 항목 |
| --- | --- | --- | --- | --- |
| 0. 수집 대상 결정 | 규칙 엔진 | AI 미사용 | 없음 | 허용 도메인, 세그먼트, 최대 자료 수 |
| 1. 자료 수집 | 조사 에이전트 | Terra / low | URL, 제목, 발행일, 원문 위치 | 도메인 허용 목록, 중복 URL, 발행일 |
| 2. 근거 추출 | 추출 에이전트 | Terra / low | 사실 문장, 수치, 인용 위치, 영향 축 | 원문 존재, 인용 길이, 수치 형식 |
| 3. 증거 분류 | 분류 에이전트 | Terra / medium | 수요·재고·가격·공급·이익의 방향과 세그먼트 | JSON 스키마, 출처군 중복 여부 |
| 4. 국면 제안 | 분석 에이전트 | Sol / high | 우호·중립·주의, 3~6개월 관점, 상반 증거 | 상태 변경 조건, 최소 증거 수, 신뢰도 상한 |
| 5. 반대 의견 감사 | 감사 에이전트 | Sol / high | 놓친 반대 근거, 과도한 일반화, 상태 하향 제안 | 모든 위험 문구 노출 여부 |
| 6. 리포트 작성 | 편집 에이전트 | Terra / low | HTML 요약과 JSON 설명 문구 | JSON Schema, 링크, 날짜, 정적 빌드 |
| 7. 배포·동기화 | 규칙 엔진 / CI | AI 미사용 | 없음 | 테스트, hash, `report_id`, 만료일 |

## 단계별 상세 규칙

### 0. 수집 대상 결정 — AI 미사용

수집 대상은 코드로 고정한다. AI가 그 주의 관심 뉴스에 따라 출처를 임의로 넓히면 반복 가능성과 편향 통제가 무너진다.

- 1차 출처: 기업 IR·실적발표·공시, WSTS, SEMI, 거래소 공시
- 세그먼트: `memory_hbm_dram`, `memory_nand`, `foundry_logic`, `equipment_materials`, `analog_auto_industrial`
- 각 자료는 URL, 발행일, 출처군, 세그먼트가 있어야 한다.

### 1~3. 수집·추출·분류 — Terra

Terra는 자료의 의미를 새로 만들지 않고, 아래 구조로 옮긴다.

```json
{
  "segment": "memory_hbm_dram",
  "pillar": "pricing",
  "direction": "positive",
  "fact": "공식 자료에 명시된 관찰 가능한 사실",
  "source_url": "https://...",
  "published_at": "YYYY-MM-DD",
  "source_family": "manufacturer_earnings",
  "confidence": "direct"
}
```

- Terra의 `fact`에는 추정, 목표주가, 매수 의견을 넣지 않는다.
- 같은 보도자료를 인용한 기사 여러 건은 하나의 출처군으로 계산한다.
- 원문이 없거나 발행일이 불명확하면 `unverified`로 저장하고 국면 점수에 반영하지 않는다.

### 4. 국면 제안 — Sol

Sol은 다음 경우에만 실행한다.

1. 이전 주와 상태가 달라질 가능성이 있을 때
2. `confidence >= 70` 후보가 생겼을 때
3. 같은 세그먼트에서 긍정·부정 근거가 동시에 강할 때

Sol의 입력은 반드시 추출·분류 완료된 JSON으로 제한한다. 원본 웹 전체를 다시 읽게 하지 않는다. 출력은 설명문이 아니라 아래 결정 형식이어야 한다.

```json
{
  "proposed_status": "favorable | neutral | caution",
  "confidence": 0,
  "horizon_months": "3-6",
  "supporting_evidence_ids": ["..."],
  "contrary_evidence_ids": ["..."],
  "reason": "근거 기반의 짧은 설명",
  "generalization_warning": false
}
```

Sol이 해야 할 일은 ‘정답 맞히기’가 아니라 다음 네 가지다.

- HBM의 증거를 NAND·아날로그 전체로 확장하지 않기
- 경영진의 전망과 실현된 지표를 구분하기
- 긍정 근거만큼 반대 근거를 명시하기
- 근거가 부족하면 `neutral`을 선택하기

### 5. 반대 의견 감사 — Sol

국면 제안과 별도 프롬프트로 실행한다. 제안 결과를 정당화하지 말고, **그 결론이 틀렸을 증거**를 찾는 것이 역할이다.

아래 중 하나라도 해당하면 상태를 `neutral`로 내리거나 `caution` 사유를 병기한다.

- 하나의 제조사·한 제품군에만 의존
- 30일 이상 된 자료가 핵심 근거
- 가격·재고·공급·이익 중 한 축만 존재
- 상반된 근거가 있는데 리포트에 빠짐
- 세그먼트와 개별 종목을 혼동

## 규칙 기반 확정 조건

AI의 제안은 아래 규칙을 통과한 뒤에만 `cycle-latest.json`에 반영한다.

| 상태 | 최소 조건 |
| --- | --- |
| 사이클 우호 | 서로 다른 출처군 2개 이상 + 긍정 증거 축 2개 이상 + Sol 감사 통과 |
| 사이클 중립 | 증거 부족, 상충, 또는 검증 실패. 기본값이다. |
| 사이클 주의 | 서로 다른 출처군 2개 이상 + 부정 증거 축 2개 이상 + Sol 감사 통과 |

- `confidence`는 85를 넘길 수 없다. 사이클 판단에는 항상 불확실성이 있다.
- 새 리포트가 검증에 실패하거나 만료되면 자동으로 `중립 · 데이터 갱신 대기`를 반환한다.
- `우호`는 SAYO의 매수 후보나 strong 신호를 새로 만들지 않는다.
- `주의`는 매도 지시가 아니며, semiconductor strong 승격을 보류하고 근거를 노출하는 용도다.

## 주간 실행 순서와 토큰 절약

1. 코드가 허용 출처의 새 자료만 수집한다. (AI 미사용)
2. Terra/low가 자료를 추출하고 중복을 제거한다.
3. Terra/medium이 증거를 다섯 축으로 분류한다.
4. 이전 상태와 같고 신뢰도 변화가 작으면 Terra 결과만으로 `중립/유지` 리포트를 만든다.
5. 상태 변경 후보 또는 상충 신호가 있을 때만 Sol/high로 국면 제안과 반대 의견 감사를 수행한다.
6. 코드가 스키마·출처·날짜·상태 조건을 검증한다. (AI 미사용)
7. 통과한 HTML 및 JSON만 배포한다.

이 설계에서는 대부분의 주에 Terra만 사용하고, Sol은 예외적으로만 호출한다.

## 모델 프롬프트 공통 제약

모든 에이전트 프롬프트에 다음을 포함한다.

> 제공된 출처 밖의 사실을 만들지 마라. 투자 추천·목표가격·매수/매도 의견을 생성하지 마라. 증거가 불충분하거나 충돌하면 중립 또는 검증 불가를 선택하라. 모든 결론에는 evidence id를 연결하라.

- [ ] 반대 근거가 사용자에게 보이는가?

- [ ] SAYO의 valuation·timing 결과와 cycle 보조지표가 분리되어 있는가?

## 모델 선정 근거

OpenAI의 현재 모델 가이드는 GPT-5.6 Sol을 복잡한 추론·코딩의 주력으로, GPT-5.6 Terra를 지능과 비용의 균형 모델로 구분한다. 따라서 수집·정규화에는 Terra를, 반도체 세그먼트의 상충 증거를 해석하고 상태 변경을 감사하는 단계에는 Sol을 쓴다.
